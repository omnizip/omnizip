== Purpose

Zstandard (zstd) is a modern, fast compression algorithm developed by Facebook that offers an excellent balance between compression ratio and speed. It significantly outperforms Deflate in both speed and compression ratio.

== Key Characteristics

[cols="1,3"]
|===
|Property |Value

|Compression Ratio
|Very good (better than Deflate)

|Compression Speed
|Very fast (3-4x faster than Deflate)

|Decompression Speed
|Extremely fast (4-5x faster than Deflate)

|Memory Usage
|Low to medium

|Best For
|Real-time compression, high-throughput applications, modern systems
|===

== When to Use Zstandard

**Choose Zstandard when**:

* Need fast compression with good ratios
* Real-time compression requirements
* High throughput is critical
* Working with modern systems and tools
* Want better performance than Deflate without LZMA's slowness

**Consider alternatives when**:

* Maximum compatibility is required (use Deflate)
* Best compression ratio needed (use LZMA2)
* Working with legacy systems

== Basic Usage

=== Compress a File (.zst)

[source,ruby]
----
# Writes a real Zstandard frame (validated by the system zstd CLI)
Omnizip.compress_file('logfile.log', 'logfile.log.zst')

# Compression level (generic 0-9 scale; values above 9 pass through
# as native zstd levels 1-22)
Omnizip.compress_file('data.bin', 'data.bin.zst', level: 9)

Omnizip.decompress_file('logfile.log.zst', 'logfile.log')
----

=== Zstandard Entries in ZIP

ZIP supports Zstandard as a per-entry method (method 93). Requires a
modern reader (e.g. 7-Zip 21+):

[source,ruby]
----
require 'omnizip/zip/output_stream'

Omnizip::Zip::OutputStream.open('fast.zip') do |zip|
  zip.put_next_entry('data.bin', compression: :zstandard, level: 3)
  zip.write(data)
end
----

== Compression Levels

Zstandard offers levels 1-22 with fine-grained control:

[cols="1,2,2,2"]
|===
|Level Range |Speed |Ratio |Typical Use

|1-3
|Very Fast
|Good
|Real-time, temporary files

|3-7
|Fast
|Very Good
|**Default** - general use

|8-15
|Medium
|Excellent
|Distribution, important data

|16-22
|Slow
|Excellent+
|Archival (approaches LZMA)
|===

.Level Performance Example
[source,ruby]
----
# Compare different Zstandard levels (native zstd scale)
[1, 12, 19].each do |level|
  time = Benchmark.measure do
    Omnizip.compress_file('data.bin', "zstd-#{level}.zst", level: level)
  end

  size = File.size("zstd-#{level}.zst")
  puts "Level #{level}: #{size / 1024} KB in #{time.real.round(3)}s"
end
----

== Performance Comparison

No benchmark tables here: Omnizip's Zstandard is a pure Ruby
implementation, so absolute throughput differs substantially from
the C library. The algorithmic trade-offs hold — faster than LZMA
per level, better ratio than Deflate — but measure on your own
workloads.

== Advanced Features

=== Dictionary Compression

A raw dictionary (shared prefix) dramatically improves ratios on
small, repetitive inputs. Dictionary *training* is not implemented;
prepare dictionary content yourself and load it with +from_raw+:

[source,ruby]
----
dict = Omnizip::Algorithms::Zstandard::Dictionary.from_raw(
  42, File.binread('shared-samples.bin')
)

zstd = Omnizip::Algorithms::Zstandard.new
File.open('data.json', 'rb') do |input|
  File.open('data.json.zstd', 'wb') do |output|
    zstd.compress_with_dict(input, output, dict)
  end
end

File.open('data.json.zstd', 'rb') do |input|
  File.open('data.restored', 'wb') do |output|
    zstd.decompress_with_dict(input, output, dict)
  end
end
----

=== Streaming

The codec is stream-oriented:

[source,ruby]
----
zstd = Omnizip::AlgorithmRegistry.get(:zstandard).new
File.open('input.log', 'rb') do |input|
  File.open('input.log.zst', 'wb') do |output|
    zstd.compress(input, output, level: 3)
  end
end
----

== Use Cases

=== Log File Compression

Perfect for compressing logs quickly:

[source,ruby]
----
# Compress today's logs rapidly
Dir.glob('/var/log/app/*.log').each do |log|
  Omnizip.compress_file(log, "#{log}.zst", level: 3)
end
----

=== Web Application Responses

Compress API responses on-the-fly:

[source,ruby]
----
require 'stringio'

class ExportController < ApplicationController
  def download
    data = generate_export_data # a String

    zstd = Omnizip::AlgorithmRegistry.get(:zstandard).new
    output = StringIO.new
    zstd.compress(StringIO.new(data), output, level: 3)

    send_data output.string,
      filename: 'export.zst',
      type: 'application/zstd'
  end
end
----

=== Database Dumps

Stream a dump into a .zst frame:

[source,ruby]
----
# Stream database dump to compressed file
require 'open3'

zstd = Omnizip::AlgorithmRegistry.get(:zstandard).new
File.open('db-backup.sql.zst', 'wb') do |output|
  # Stream pg_dump output directly
  Open3.popen3('pg_dump mydb') do |_stdin, stdout, _stderr, _wait_thr|
    zstd.compress(stdout, output, level: 7)
  end
end
----

== Best Practices

. **Use Level 3-5 for General Use**: Excellent speed/ratio balance
. **Level 1 for Real-Time**: When speed is critical
. **Level 10+ for Archival**: When time permits better compression
. **Train Dictionaries**: For repetitive data types (JSON, logs)
. **Monitor Performance**: Should achieve 50-200 MB/s compression

== Command-Line Usage

[source,bash]
----
$ omnizip compress data.bin data.bin.zst --algorithm zstandard

# The output is a standard Zstandard frame, readable by the system
# zstd CLI
----

== Technical Details

**Zstandard Features**:

* **Fast Entropy Encoding**: Finite State Entropy (FSE)
* **Adaptive Window**: Dynamically sized based on level
* **Dictionary Compression**: Raw-dictionary priming (entropy-table
  preloading from RFC dictionaries is not implemented)
* **Frames**: Interoperable with the reference zstd CLI (verified
  both directions)

**Implementation**: Pure Ruby, part of Omnizip. No native binding.

**Not available**: Zstandard is not offered as a 7z coder method;
in 7z archives use LZMA2/PPMd/BZip2. Multi-threading is not
implemented (single-threaded encoder).
